# 工作流契约

## 状态机

| 状态 | 可执行动作 | 进入下一状态的唯一条件 |
|---|---|---|
| `INPUT` | 核对原始文本；未提创作者时默认通用模式 | 已具备原始文本；通用模式已成立，或用户选择了创作者模式 |
| `CREATOR_PENDING` | 仅在用户主动要求推荐或指定库外创作者时等待选择 | 用户明确选择创作者，或明确返回通用模式 |
| `DRAFT_PENDING` | 输出导演讲戏与单行草稿并停止 | 用户回传完整修订草稿，或明确且无歧义地批准当前完整草稿 |
| `DRAFT_LOCKED` | 可进入详细设计，或等待用户明确提出长镜头合并 | 用户选择下一项动作 |
| `LONG_TAKE_PENDING` | 输出完整修订草稿并再次停止 | 用户回传完整修订稿，或明确且无歧义地批准当前完整修订草稿 |
| `FINAL_DRAFT_LOCKED` | 执行详细镜头设计 | 原始文本、最终草稿、确认记录和当前模式齐全；创作者资料仅在创作者模式必需 |

## 批准语义

- `草稿不做修改`、`这版没问题，锁定吧`、`确认按当前完整草稿执行` 等明确指向当前完整草稿，并表达无修改、批准或锁定意图的回复，可以从 `DRAFT_PENDING` 或 `LONG_TAKE_PENDING` 开门。
- 孤立的 `继续`、`下一步`、`可以`、`往下` 等泛化推进语没有明确批准对象，不得开门；要求用户补充是否锁定当前完整草稿。
- 不得仅根据积极语气推断批准，也不得把隐藏剪辑实现方式的接受解释为完整草稿批准。

## 三个 Skill 的边界

- 草稿 Skill 决定镜头拆分、镜头顺序、分镜节奏、景别、可见动作和原有台词；不做摄影设计。
- 长镜头 Skill 只改变用户指定范围的草稿结构；不做最终机位、运镜或焦段设计。
- 详细设计 Skill 只扩写锁定草稿；不得重拆、合并、增删或重排镜头，不得重新评价、调整分镜节奏或景别。

发生边界冲突时，报告冲突的镜头 ID 和缺失材料，然后停止。不得在同一回答中悄悄修订草稿并继续详细设计。

## 创作者资料边界

- 通用模式不读取创作者索引或原文，不以缺少创作者为由暂停。
- 创作者模式的草稿与详细设计 Skill，都从 `directing/creator-index.md` 路由并读取选中创作者的 `directing/library/` 完整原文。
- 一次任务只加载主参考的完整原文。只有用户明确指定辅助参考及其单一作用维度时，才额外加载一份。
- 索引用于找文件，不是创作者方法摘要，不得代替原文。

## 回滚

详细设计完成后若用户要求合并镜头：

1. 标记受影响的详细镜头失效；
2. 回到 `DRAFT_LOCKED`；
3. 执行长镜头合并；
4. 输出完整修订草稿并重新等待批准；
5. 只在再次批准后重做受影响的详细镜头，并复核全场连续性。
