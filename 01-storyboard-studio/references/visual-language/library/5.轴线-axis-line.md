# 轴线 / 越轴 (The Line / 180° Rule)

> **一句话核心**：轴线是**唯一一个「单镜头全对、组接起来全错」的规则**——每个镜头单看都合法，接在一起观众却瞬间懵。
> 它是跨镜头的隐性约束，在生成式视频里格外要命，因为模型一次只生成一个镜头，根本不知道「轴线」这个跨镜头约束的存在。

---

## 一、SSOT：轴线到底是什么

轴线（the line / axis）**不是相机的线，是被拍主体之间的一条关系线**。这是最常被搞反的第一性问题。

| 轴线类型 | 由什么定义 | 例子 |
|---|---|---|
| **关系轴线** | 两个人之间的连线 | A 和 B 对话，连接两人的直线 |
| **运动轴线** | 主体的运动方向 | 一辆车向右行驶，行驶方向就是轴线 |
| **视线轴线** | 主体的朝向/注视方向 | 一个人望向画外某物，视线方向即轴线 |

**核心机制**：这条轴线把空间劈成两半。相机**只要始终待在轴线的同一侧（180° 半圆内），观众的左右方位感就守恒**——A 永远在左，B 永远在右，谁看谁的方向永远一致。这就是 **180° 法则（180-degree rule）**。

> 轴线是**场景内的客观事实**，不是相机的属性。相机只是选择「站在轴线哪一侧」。
> 搞清这个主客关系，后面全通。

> **上游归属**：轴线的「因」在**调度**——是人物**怎么站**（关系连线 / 运动方向 / 视线方向）决定了轴线在哪，不是反过来。
> 本文档是轴线作为**组接约束**的展开；轴线的源头（人物站位）见 `blocking.md`（调度，上游根节点）。

## 二、180° 法则的几何机制

想象 A、B 对坐，连线就是轴线。轴线一侧是「允许区」（180° 半圆），另一侧是「禁区」：

```
        [ 允许区：相机在这半边随便动 ]
   cam1        cam2        cam3
     \          |          /
      \         |         /
   A ●━━━━━━━━━━━━━━━━━━━● B   ← 轴线
      /         |         \
     /          |          \
        [ 禁区：越过就翻转 ]
```

**在允许区内**，无论相机怎么移、推拉摇移、切多少个机位：
- A 始终在画面左，B 始终在画面右
- A 始终朝右看，B 始终朝左看（视线相对，「对上了」）
- 过肩镜头里，越过谁的肩、看谁的脸，左右关系稳定

**一旦相机跳到禁区（越轴）**：
- A、B 左右位置**突然对调**
- 两人从「相视」变成「**朝同一个方向看**」——观众瞬间以为他们不再看对方，或空间被重置了

## 三、越轴的视觉后果（为什么观众会懵）

越轴不是「画面难看」，是**观众的空间模型被强制刷新**。三种崩坏：

| 后果 | 现象 | 观众的错觉 |
|---|---|---|
| **左右对调** | A 从左跳到右 | 「他们换位置了？他们移动了？」 |
| **视线脱靶** | 两人从相视变同向 | 「他们不看对方了？在看别的东西？」 |
| **运动反向** | 向右开的车下一镜向左开 | 「车掉头了？这是另一辆车？」 |

> 最典型的是**追逐戏**：追的人和被追的一直向右跑，观众才知道「谁追谁、往哪追」。
> 一旦某镜把某人拍成向左跑，观众立刻分不清方向，紧张感崩盘。
> **运动轴线的越轴比对话轴线更致命**，因为它直接摧毁地理逻辑。

## 四、别混淆：30° 法则是另一条规则

常和 180° 法则一起讲，但**管的是完全不同的事**，做 field-split 一定要切开：

| | 180° 法则 | 30° 法则 |
|---|---|---|
| 管的是 | 相机在轴线**哪一侧** | 相邻两镜的相机**夹角够不够大** |
| 违反后果 | 左右翻转、方位崩坏 | **跳切感**（jump cut），画面「抖一下」 |
| 触发条件 | 越过轴线 | 相邻镜位移 <30° 且景别没变 |

**30° 法则**：同一主体，相邻两镜的机位夹角**至少差 30°**（且最好景别也跨级），否则观众看到的就像同一镜「突然跳了一下」——变化太小，大脑判定为「剪辑失误」而非「换了个视角」。

> 呼应景别的「景别三角原则」：**变化要么足够大（换视角），要么就别换**，中间地带最难看。
> 两条法则正交——一个管左右不能翻，一个管相邻不能太像。合法组接必须**同时满足**。

## 五、合法越轴：怎么破轴而不出戏

轴线不是不能破，是不能**「硬跳」破**。给观众一个「重置提示」即可合法过轴。五种手段：

| # | 手段 | 做法 | 特点 |
|---|---|---|---|
| ① | **骑轴过渡镜** | 用运动镜头让相机**当着观众的面**从一侧移到另一侧（弧形/环绕） | 最「诚实」，空间连续，不会懵 |
| ② | **中性镜 / 骑线镜** | 插一个**正对轴线**的镜头（正面直拍，谁都不偏）当缓冲垫 | 本身无左右倾向，下一镜可合法落到另一侧 |
| ③ | **主体自己动** | 让 A 起身走动、转身，**主体一动轴线就重画** | 最自然——不是相机偷偷越轴，是关系本身变了 |
| ④ | **插入镜头 / 特写切断** | 切一个不含方位信息的镜头（手、钟、空镜）清空空间缓存 | 「重置」按钮，用多了廉价 |
| ⑤ | **大远景重新建立** | 回到大景别把新空间关系重新交代 | 最稳但最「重」，会打断节奏 |

## 六、复杂场景：多人、移动、多组轴线

两人对话是最简单的单轴线。真实分镜里轴线会**增殖**，这才是 blocking 分析的真正战场：

**三人及以上**
每对关系都有一条轴线，n 人有 C(n,2) 条潜在轴线，不可能全守。
→ **选一条主轴线（当前戏剧焦点的那一对）优先锁死**，次要关系服从主轴。焦点转移时用合法手段显式过渡到新主轴。
> **主轴线的选择本身就是导演调度**——你在决定「这一刻观众该盯谁和谁的关系」。

**主体移动**
人走、车行时轴线是活的。原则：**在主体停下、建立新静止关系前，相机不要抢先越轴**。运动中过轴必须靠骑轴运镜（手段①），不能靠剪辑硬跳。

**多组分离的关系**
一场戏两组人（吧台两人 + 门口两人）= 两套独立轴线系统。切换组别相当于进入新子空间，需用建立镜重新交代，观众才不会把两套左右关系混淆。

**群戏 / 圆桌**
人围成一圈，严格线性轴线失效。这时靠**每个人稳定的「注视方向 + 相对位置」的整体一致性**，而非单一轴线。实操上预先画一张俯视 blocking 图，锁定每个人朝向，逐镜核对。

## 七、生成式视频语境：轴线为什么在这里格外要命

传统拍摄里轴线是「摄影机纪律」；在 Seedance / 即梦这类模型里，轴线是**你必须从外部强加的约束**：

| 传统拍摄 | 生成式视频 |
|---|---|
| 一场戏连续拍，空间物理连续 | **每个 clip 独立采样**，模型不知道上一镜 A 在左 |
| 越轴是「选错机位」 | 越轴是「两个 clip 各自合法，拼起来翻转」 |
| 靠现场摄影指导守轴 | 靠**关键帧 / 提示词 / 首尾帧**从外部锁死 |

**模型不理解跨镜头的轴线**——它只对当前这一条提示词负责。典型崩坏：
- 镜头 A：提示「两人对话，男左女右」→ 生成时男在左 ✓
- 镜头 B：提示「女方特写反应」→ 模型自由发挥，把女方拍成朝右看，接上去视线脱靶

### 对策（映射回 blocking-analysis 层）

**① 轴线作为全场约束，不是逐镜提示。**
在约束 brief 里先声明整场的轴线方向和每个角色的固定屏幕方位（「A 恒定 screen-left 朝右，B 恒定 screen-right 朝左」），然后**每一条 Seedance 提示词都显式带上该角色的朝向和屏幕位置**。模型没有记忆，每一镜都要重申。

**② 用首帧 / 首尾帧锁死方位。**
生成式独有的强手段——靠提示词的方位描述不够稳，就用**参考图直接钉死**：给关键镜的首帧一张已摆好左右关系的图，模型采样被约束在正确方位里。
> blocking 层「首帧/首尾帧控制档位」的判断，本质就是在决定「这一镜的轴线风险高不高、要不要用图锁死」。

**③ 过肩 / 正反打配对，方位必须成套设计。**
OTS 正反打是越轴重灾区。生成时把「越过 A 肩看 B」和「越过 B 肩看 A」**作为一对同时设计**，明确两张图里 A、B 的左右必须镜像一致，而不是分别生成后祈祷它们对得上。

**④ 高风险镜显式标注。**
把「涉及视线相对 / 运动方向 / 多人同框」的镜头标为轴线高风险，优先用图控（首尾帧）；纯文字档留给方位无关的镜头（空镜、大远景、单人特写）。这就是控制档位分级的核心依据之一。

## 八、落地：轴线进 spec 的字段结构

```yaml
scene_axis (场景轴线，全场级 SSOT):
  primary_axis:
    type: 关系 / 运动 / 视线
    definition: <A—B 连线 / 运动方向>
    camera_side: 锁定在轴线哪一侧
  screen_positions:                    # 每个角色的恒定屏幕方位
    A: {screen_side: left,  facing: right}
    B: {screen_side: right, facing: left}
  axis_risk: 高 / 中 / 低              # 决定控制档位

per_shot (逐镜继承):
  inherits_axis: primary_axis
  A_position: left      # 每镜必须重申，模型无记忆
  B_position: right
  control_tier: 纯文字 / 首帧 / 首尾帧   # 由 axis_risk 决定
  crossing_method: null / 骑轴运镜 / 中性镜 / 主体转身  # 若本镜需要过轴
```

---

> **一句话收束**：传统拍摄里轴线是「别踩的线」，生成式视频里轴线是「**每一镜都要重新画上去的线**」——因为模型不会替你记住上一镜谁在左边。
> blocking 层的价值，一大半就在于**把这条跨镜头的隐性约束，翻译成每一条提示词都能独立执行的显式方位指令 + 图控档位**。

## 附：关联维度

- **调度（上游根节点）**：人物站位 → 轴线的「因」。轴线在哪，由 `blocking.md` 的站位决定
- **机位 / 水平朝向（Pan）**：越轴与相机绕主体的方位直接耦合
- **相机运动**：运动轴线的越轴靠骑轴运镜解决；过轴手段①依赖运动
- **景别**：30° 法则与景别三角原则同源（相邻镜变化要够大）
- **OTS 正反打**：越轴最高发的综合战场，方位需成对镜像守恒（另属文档）
- **视点归属**：过肩（OTS）是半主观视点，是越轴重灾区
