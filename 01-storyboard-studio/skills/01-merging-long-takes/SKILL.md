# 01-长镜头合并

评估已锁定草稿中的长镜头候选，或把用户明确指定的相邻镜头改写成一个连续长镜头草稿。它位于草稿锁定之后、详细镜头设计之前；允许推荐，禁止未授权执行。

## 先加载

1. 读取 [工作流契约](../../references/workflow-contract.md)。
2. 读取 [长镜头合并契约](../../references/long-take-contract.md)。
3. 合并涉及复杂走位或多轴线时，读取[调度规则](../../references/visual-language/rules/6-blocking-rules.md)和[轴线规则](../../references/visual-language/rules/5-axis-line-rules.md)，但只用于判断能否连续，不提前设计摄影。

## 入口门槛

先判断用户请求属于哪一种：

### 候选推荐

- 必须具备一份已经确认的完整草稿，以及询问“哪些镜头适合合并”“能否推荐长镜头区间”等明确推荐请求。
- 用户不需要预先提供镜头 ID。检查同场、相邻、时间连续、动作因果、人物位置、道具状态和信息揭示后，推荐一至三个候选范围。
- 每个候选只写镜头 ID、适配原因、主要代价，以及属于真实长镜头还是可能需要隐藏剪辑。
- 候选推荐不会修改草稿、删除编号、生成 `-LT` 镜头或替用户选择。输出建议后停止，等待用户明确选定范围并提出合并请求。

### 实际合并

必须同时具备：一份已经确认的完整草稿、用户明确指定的镜头 ID，以及明确的合成长镜头或一镜到底请求。缺少任一项就停止索取；不得把“这个建议不错”等评价自动解释为执行授权。

若用户在详细镜头设计完成后提出合并，先声明受影响设计将失效，按工作流契约退回本阶段；不要直接修改详细分镜。

## 连续性判定

按草稿顺序逐项确认选中镜头是否同场、相邻、时间连续、动作因果可连接，并且人物位置、道具状态与信息揭示没有不可跨越的重置。

- 非相邻、跳时、跳场或动作无法连续：列出具体镜头 ID 和原因，停止。
- 只有使用隐藏剪辑才可实现：说明隐藏点、模拟方式和代价，等待用户明确接受；未接受前停止。
- 可以真实连续完成：继续合并。

## 合并

1. 为每个选中镜头登记主要动作、原台词、关键道具状态、人物进出、视线变化和信息揭示。
2. 按原顺序连接，允许改写句法，不得删节信息、改变台词或提前揭示。
3. 默认用首镜 ID 加 `-LT`，例如 `S05-LT`。
4. 只描述长镜头的景别起止和连续可见动作；禁止写最终机位、纵轴向方位角、俯仰、焦段、具体运镜和设备。
5. 删除被吸收的独立编号；其他编号和顺序保持不变，不重排。

## 固定格式

```text
合并关系：S05-LT ← S05、S06、S07、S08
S05-LT｜长镜头，中景起至近景止（林禾、周芸）｜按原顺序连接的完整动作。｜林禾：{“今天有我的信吗？”}
```

输出合并可行性、合并关系、完整修订草稿和信息保真核对。完整修订草稿必须包含合并范围之外的全部镜头。

## 再次审批

输出完整修订草稿后再次暂停。只有用户回传完整修改稿，或明确且无歧义地批准当前完整修订草稿，才能进入详细设计。

`草稿不做修改`、`这版修订稿没问题，锁定吧` 等明确批准有效。孤立的 `继续`、`下一步`、`可以`、`往下` 或沉默都不构成批准。隐藏剪辑的接受也只批准实现方式，不自动批准修订草稿。
